## Projects

<details>
<summary><b>CrowdEase</b>, transit analytics on TransJakarta's real GTFS feed</summary>
<br>

A Go spatial-hash walkshed engine computes real 500m coverage for all 8,091 stops, avoiding a roughly 130 million calculation naive nearest-stop search. A batched ingestion pipeline loads about 252,000 real GTFS rows into Postgres in under 600 round trips. The rider-facing demo replays buses along their real route paths and estimates the best time to ride, clearly labeled as an estimate rather than measured ridership.

Stack: NestJS, Next.js, PostgreSQL, Go, Leaflet
Links: [live demo](https://portofavolio-rmww.vercel.app) · [code](https://github.com/favizz/Portofavolio)
</details>

<details>
<summary><b>Netflow</b>, IoT prepaid utility metering system</summary>
<br>

A NestJS + MySQL backend streams live MQTT telemetry from 2,444+ smart meters into prepaid token billing, with two React frontends (a building-manager dashboard and a resident app). A 13-detector anomaly engine (backflow, tamper, sensor faults, MCB trips) is backed by 166 unit tests. Multi-tenant access is secured with Google OAuth 2.0, JWT, and RBAC.

Stack: NestJS, TypeScript, React, MySQL, Redis, MQTT
Links: [code](https://github.com/favizz/netflow)
</details>

<details>
<summary><b>Fraud Detection</b>, ML algorithms from scratch</summary>
<br>

A fraud classification pipeline on a real, severely imbalanced dataset (about 100k transactions, 14% fraud). Decision Tree, Logistic Regression, and KNN were implemented from scratch by a 4-person team and benchmarked against scikit-learn. Class weighting and SMOTE took fraud recall from 0.02 to 0.52, a 25x cut in false negatives. My own part: the preprocessing pipeline, EDA, the scikit-learn benchmark implementations, and the live demo web app.

Stack: Python, scikit-learn
Links: [live demo](https://fraud-detection-using-machine-learn.vercel.app) · [code](https://github.com/favizz/Fraud-Detection-using-Machine-Learning-Algorithm)
</details>

<details>
<summary><b>Genyra</b>, genealogy platform</summary>
<br>

A full-stack application (NestJS, Next.js, PostgreSQL) on a shared-type monorepo. A custom multi-phase auto-layout engine positions family members across generations without manual placement, handling multi-marriage and overlapping-branch cases. BFS-based consanguinity checks flag close-relative conflicts up to 3 generations before a relationship can be saved.

Stack: NestJS, Next.js, PostgreSQL, React Flow
Links: [live demo](https://genyra-familytree.vercel.app) · [code](https://github.com/favizz/genyra-familytree)
